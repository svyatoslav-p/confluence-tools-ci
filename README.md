# Confluence Tools CI

Модульное расширение Chrome (Manifest V3) с инструментами для Confluence Data Center 9.x.
Работает целиком в браузере, установка плагина на сервер Confluence не нужна.

## Сборка и установка

```bash
npm install
npm run build
```

1. Откройте `chrome://extensions` и включите «Режим разработчика».
2. Нажмите «Загрузить распакованное расширение» и выберите папку `.output/chrome-mv3`.
3. Откроется страница настроек. Для каждого адреса Confluence нажмите «Выдать доступ».
4. Обновите открытые страницы Confluence.

`npm run zip` собирает архив для передачи другим пользователям (распаковать и загрузить так же).
`npm run icons` заново создаёт иконки в `public/icon/` из `assets/icon.svg`.
`npm run dev` запускает режим разработки с автообновлением, `npm run compile` проверяет типы.

## Готовая сборка из GitHub Actions

Workflow **Build Chrome extension** автоматически запускается при push в `main`
и pull request в эту ветку. Он устанавливает зависимости по lock-файлу, проверяет
типы и тесты, собирает Chrome Manifest V3 и проверяет состав сборки. ZIP публикуется
только после успешного прохождения всех шагов.

Чтобы скачать расширение без локальной сборки:

1. Откройте [Actions → Build Chrome extension](https://github.com/svyatoslav-p/confluence-tools-ci/actions/workflows/build-chrome.yml).
2. Выберите успешный запуск для нужного коммита в ветке `main`.
3. В разделе **Artifacts** скачайте `confluence-tools-ci-chrome.zip`.
   Для скачивания нужно войти в GitHub. Артефакт хранится 30 дней.
4. Распакуйте ZIP в постоянную папку. В её корне должен находиться `manifest.json`.
5. Откройте `chrome://extensions`, включите «Режим разработчика», нажмите
   «Загрузить распакованное расширение» и выберите эту папку.
6. В настройках расширения выдайте доступ к адресу Confluence и перезагрузите страницу.

Для ручной сборки на той же странице Actions нажмите **Run workflow**, выберите
ветку и подтвердите запуск. При обновлении уже установленного расширения распакуйте
новую сборку в прежнюю папку, нажмите «Обновить» у расширения и перезагрузите Confluence.

## Использование

- На страницах Confluence справа внизу появляется круглая кнопка с волшебной палочкой: меню действий и пункт «Настройки…».
- **Панель быстрого форматирования.** В редакторе выделите текст и зажмите Ctrl — над выделением
  появится панель: очистить стиль, красный зачёркнутый, зелёный, жёлтый. Те же действия доступны
  по горячим клавишам (по умолчанию Alt+Z, Alt+X, Alt+C, Alt+V).
  В настройках можно включить показ панели сразу при выделении, без Ctrl.
- В настройках задаются адреса Confluence, включение модулей, цвета и горячие клавиши.
- Интерфейс расширения автоматически повторяет светлую или тёмную тему Confluence.

## Структура

```
entrypoints/
  background.ts   подключает расширение к адресам из настроек
  bridge.ts       скрипт расширения на странице: передаёт настройки коду страницы
  app.ts          код в контексте страницы (доступ к tinymce)
  options/        страница настроек
core/             каркас: типы, реестр модулей, настройки, меню, тема
features/         модули, по одной папке на функцию
  <имя>/definition.ts  название и настройки, только данные
  <имя>/index.ts       реализация функции
.agents/skills/   проектные скилы Codex
AGENTS.md         инструкции для работы Codex с проектом
```

Код модулей выполняется в контексте страницы Confluence, потому что только там доступен
редактор TinyMCE. К `chrome.*` у него доступа нет: настройки ему передаёт `bridge.ts`.

## Как добавить функцию

Создайте два файла в `features/<имя>/`. Описания и реализации подхватываются
автоматически разными реестрами, другие модули менять не нужно.
`definition.ts` содержит только данные, необходимые странице настроек и хранилищу:

```ts
// features/my-feature/definition.ts
import type { FeatureDefinition } from '../../core/types';

const definition: FeatureDefinition = {
  id: 'my-feature',
  title: 'Моя функция',
  description: 'Что она делает',
  settings: [{ key: 'color', label: 'Цвет', type: 'color', default: '#0052cc' }],
};

export default definition;
```

`index.ts` дополняет описание исполняемым кодом, который нужен только на странице Confluence:

```ts
// features/my-feature/index.ts
import type { Feature } from '../../core/types';
import definition from './definition';

const feature: Feature = {
  ...definition,
  actions: [
    {
      id: 'run',
      title: 'Выполнить',
      mode: 'view', // 'view' | 'editor' | 'any'
      run: async (ctx) => {
        ctx.notify(`Цвет: ${ctx.values.color}`, 'success');
      },
    },
  ],
  // setupEditor(ctx) { ...; return () => { /* убрать за собой */ }; },
};

export default feature;
```

Свои элементы интерфейса добавляйте в `ctx.root` и берите цвета из переменных `--ct-*`
(`core/theme.ts`), например `background: var(--ct-bg); color: var(--ct-text)` — тогда модуль
сам получит светлую и тёмную тему. Типы настроек: `color`, `hotkey`, `text`, `boolean`.

`definition.ts` не должен импортировать `index.ts` или обращаться к странице.
Инициализацию DOM и TinyMCE в реализации выполняйте внутри `setupEditor` или действия меню.
Возвращённая из `setupEditor` функция должна снять обработчики и убрать UI.
При изменении настроек каркас пересоздаёт только затронутый модуль; при смене
редактора — все его модули.

`startApp()` возвращает функцию полной очистки: модулей, таймеров, подписки на
сообщения и наблюдения за темой. Удаление адреса из настроек приостанавливает UI;
повторное добавление запускает его снова. Страницы в back/forward cache сохраняют состояние.

## Работа с Codex

Инструкции по архитектуре, проверкам и согласованному поведению находятся в
`AGENTS.md`. Проектные скилы хранятся в `.agents/skills/`: `find-skills`,
`code-review-and-quality` и `typescript-best-practices`.
Каталог `.claude/` заменён стандартным каталогом скилов Codex.

Обновления расширения выполняются вручную: после изменений выполните
`npm run compile` и `npm run build`, обновите расширение в Chrome и перезагрузите
страницу Confluence. Скачивания исполняемых модулей из удалённого репозитория нет.

## Проверка кода

Все команды выполняйте в PowerShell или терминале из каталога расширения:

```powershell
cd D:\ai\chatgpt\confluence\confluence-ext
```

Нужны установленные Node.js и npm. Если зависимости ещё не установлены, выполните
один раз `npm ci`. Перед обычным повторным запуском тестов устанавливать их заново не нужно.

### Тесты логики

```powershell
npm test
```

Запускает все файлы `tests/*.test.mjs`: настройки, сообщения, горячие клавиши,
показ панели, работу со списками, перезапуск модулей и очистку ресурсов.
Предварительная сборка, запущенный Chrome и доступ к стенду Confluence не нужны.
Тесты используют замены DOM, TinyMCE и API Chrome; они не заменяют проверку
установленного расширения в настоящем редакторе.

Для запуска одного файла, например проверок панели:

```powershell
node --test tests/toolbar.test.mjs
```

### Проверка готовой сборки

```powershell
npm run test:bundle
```

Команда сначала собирает расширение в `.output/chrome-mv3`, затем проверяет, что
реализация панели осталась в `app.js` и не попала в background, bridge или страницу
настроек. Также проверяется отсутствие каталога настроек функций в background.

### Полная проверка после изменений

Выполните последовательно; при ошибке исправьте её перед следующим шагом:

```powershell
npm run compile
npm test
npm run test:bundle
```

`compile` проверяет типы TypeScript. Отдельный `npm run build` в этой последовательности
не нужен: сборку уже выполняет `test:bundle`.

Успешные тесты выводят `fail 0`. При провале появляется название проверки и причина,
а команда завершается с ненулевым кодом. Успешные тесты не гарантируют правильное
оформление и поведение в Confluence: после них обновите расширение в Chrome,
перезагрузите страницу и проверьте изменённую функцию вручную.

Результаты ревью и границы проверки описаны в `docs/review-2026-11-17.md`.
