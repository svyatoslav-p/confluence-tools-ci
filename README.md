# Confluence Tools CI

Расширение Chrome с инструментами для Confluence Data Center 9.2.2. Работает в браузере без установки плагина на сервер Confluence.

## Установка в Chrome

1. Откройте последний выпуск и скачайте файл `confluence-tools-ci-chrome-<версия>.zip` из раздела **Assets**. [Выпуски на GitHub](https://github.com/svyatoslav-p/confluence-tools-ci/releases)
2. Распакуйте ZIP в постоянную папку. В её корне должен быть файл `manifest.json`.
3. Откройте `chrome://extensions`, включите «Режим разработчика» и нажмите «Загрузить распакованное расширение». Выберите папку из предыдущего шага.

## Первый запуск и модули

Нажмите значок Confluence Tools CI в Chrome и откройте «Настройки». На вкладке «Адреса сервисов» введите адрес Confluence с протоколом и портом, если он указан в адресной строке. Нажмите «Добавить», подтвердите доступ в Chrome и перезагрузите страницу Confluence.

Модули можно включать в меню значка Chrome и настраивать на вкладке «Модули».

- Оформляйте и преобразуйте выделенный текст в редакторе. [Панель быстрого форматирования](src/features/selection-toolbar/README.md)
- Переносите данные из таблицы «Задачи» дочерней страницы в историю родителя. [Добавить в историю](src/features/change-history/README.md)
- Создавайте черновик на основе последней дочерней версии. [Создать новую версию](src/features/new-version/README.md)
- Разворачивайте или сворачивайте спойлеры и сворачиваемые блоки кода на странице. [Развернуть/Свернуть спойлеры](src/features/spoilers/README.md)

## Обновление установленного расширения

1. Нажмите значок Confluence Tools CI в Chrome и откройте «Настройки» → «Обновление».
2. Нажмите **«Разрешить проверку обновлений»** и подтвердите запрос Chrome на доступ к GitHub (`api.github.com`). Этот доступ нужен для автоматической и ручной проверки.
3. Чтобы проверить сразу, нажмите «Проверить обновление». Если доступна новая версия, её номер появится на вкладке, а на значке расширения появится `!`.
4. Если появится кнопка «Разрешить скачивание с GitHub», нажмите её и подтвердите отдельный запрос Chrome. Затем нажмите «Установить обновление». Если Chrome попросит выбрать папку, укажите ту, из которой загружено расширение, и разрешите запись. После установки перезагрузите страницы Confluence.

Автоматическая проверка включена по умолчанию. Если снять флажок «Автоматически проверять обновления», проверка будет запускаться только кнопкой «Проверить обновление». Ссылка «Открыть сборки» всегда доступна на вкладке «Обновление».

Для ручного обновления распакуйте ZIP нового выпуска поверх файлов в папке установленного расширения, нажмите кнопку перезагрузки на его карточке в `chrome://extensions` и перезагрузите страницы Confluence.

## Сборка из исходников

Исходники расширения находятся в `src/`. Точки входа WXT лежат в `src/entrypoints/`, модули в `src/features/`, общий код в `src/core/`.

Установите Node.js 24 с npm. Затем выполните команды сборки в корне репозитория.

```bash
npm ci
npm run build
```

Готовую папку `.output/chrome-mv3` можно загрузить как распакованное расширение по инструкции выше. Команда `npm run zip` создаёт ZIP в `.output/`, а `npm run dev` запускает режим разработки WXT.

## Проверка и тесты

Установите зависимости и запустите проверки из корня репозитория.

```bash
npm run compile
npm test
npm run test:bundle
```

`npm run compile` проверяет типы TypeScript. `npm test` запускает тесты логики без Chrome и Confluence. `npm run test:bundle` собирает и проверяет расширение.

## Выпуск новой версии

Начните с актуальной ветки `main` и чистой рабочей копии. Для выпуска версии `0.1.8` выполните следующие команды из корня репозитория.

```bash
npm version 0.1.8 --no-git-tag-version
git add package.json package-lock.json
git commit -m "chore: release version 0.1.8"
git tag -a v0.1.8 -m "Release version 0.1.8"
git push --atomic origin main refs/tags/v0.1.8
```

`npm version` обновляет `package.json` и `package-lock.json`. WXT берёт версию манифеста из `package.json`. Тег должен иметь вид `v<версия>` и указывать на коммит в `main`. После отправки тега GitHub Actions запустит проверки, соберёт ZIP и опубликует его в GitHub Releases. [Workflow сборки и выпуска](.github/workflows/build-chrome.yml)
