# Добавить в историю

В режиме просмотра дочерней страницы откройте меню плавающей кнопки и выберите
«Добавить в историю». Кнопка ⓘ рядом с пунктом открывает всплывающее описание
функции поверх страницы, не меняя размеры меню. Повторное нажатие или Escape закрывает подсказку.
Модуль можно включить или выключить на вкладке «Модули».

Из опубликованной дочерней страницы берётся одна строка таблицы под заголовком
«Задачи»: SA Task, Story, Ответственный аналитик, Описание. Она переносится в
таблицу под заголовком «История» непосредственного родителя. Пятая колонка «Версия»
содержит ссылку на дочернюю страницу; подпись — версия в начале её названия
(например, `[v1.1]`), а при её отсутствии — полное название.

Повторный запуск обновляет первые четыре ячейки существующей записи, сохраняя
ссылку. При добавлении и обновлении строки сортируются по возрастанию версии:
`1.0`, `1.1`, `1.2`, `1.10`, `2.0`. Части номера сравниваются как числа.
Версия определяется по пятой ячейке или названию страницы в её ссылке.
Строки без распознаваемого номера помещаются в конец, сохраняя взаимный порядок;
равные версии также сохраняют порядок. Заголовок и остальная разметка страницы,
списки, упоминания и макросы сохраняются. Если данные и порядок не изменились, новая версия
родителя не создаётся. Таблицы с объединёнными ячейками, неоднозначные таблицы и
дублирующие записи отклоняются с сообщением об ошибке. При конфликте версий
повторите действие: чужие изменения автоматически не перезаписываются.

## Настройки поиска таблицы истории

На вкладке «Модули» в блоке «Добавить в историю» задаются:

| Параметр | По умолчанию |
|---|---|
| Заголовок раздела над таблицей | История |
| Название первой колонки (SA Task) | SA Task |
| Название второй колонки (Story) | Story |
| Название третьей колонки (аналитик) | Ответственный аналитик |
| Название четвёртой колонки (описание) | Описание |
| Название пятой колонки (версия) | Версия |

Если заголовок раздела пустой, поиск ведётся только по названиям колонок.
Иначе проверяется ближайший заголовок перед таблицей. Регистр и лишние пробелы
не учитываются. Названия всех пяти колонок обязательны и должны различаться.
Порядок колонок остаётся фиксированным: настройки меняют их названия, но не назначение.
Если найдено несколько подходящих таблиц или ни одной, запись не выполняется.

Настройки относятся к таблице родительской страницы. Источник на дочерней странице
по-прежнему ищется под заголовком «Задачи» с четырьмя стандартными колонками.
Значения сохраняются автоматически; кнопка «По умолчанию» сбрасывает параметры модуля.

## Реализация

- `definition.ts` — название и описание модуля для меню и настроек.
- `index.ts` — чтение опубликованной страницы и родителя через REST API, проверка ошибок и сохранение новой версии родителя. Повторные нажатия во время запроса блокируются.
- `tables.ts` — поиск таблиц, проверка структуры и изменение только нужного фрагмента исходной разметки.

Сервер и путь установки Confluence определяются по текущей странице. Отдельные учётные данные не требуются: используется текущая сессия браузера.

Тесты запросов и обработки ошибок находятся в `tests/change-history.test.mjs`, справка меню проверяется в `tests/app.test.mjs`. Общие команды проверки описаны в основном [README](../../README.md#проверка-кода).
