# Confluence Tools CI

Расширение Chrome Manifest V3 для Confluence Data Center 9.2.2.
Стек: TypeScript, WXT, DOM/CSS без UI-фреймворка. Интерфейс русский.
Серверный плагин устанавливать нельзя.

## Команды

- `npm ci` — установка зависимостей по lock-файлу.
- `npm run compile` — проверка типов.
- `npm test` — регрессионные тесты ядра и панели.
- `npm run test:bundle` — сборка и проверка разделения кода между контекстами.
- `npm run build` — сборка в `.output/chrome-mv3`.
- `npm run zip` — архив для ручной установки.
- `npm run icons` — генерация PNG из `assets/icon.svg`.
- `npm run dev` — режим разработки WXT.

После изменений выполняйте проверку типов и сборку. Не выдавайте успешную сборку
за проверку поведения в браузере: в отчёте укажите, что реально проверено.
Сборку пользователь обновляет через chrome://extensions, затем перезагружает
Confluence. Автоматическая загрузка и исполнение модулей из сети отменены пользователем;
сохраняйте обычную локальную сборку и ручное обновление.

## Архитектура

- `entrypoints/background.ts` — регистрация скриптов на разрешённых хостах,
  открытие страницы настроек.
- `entrypoints/bridge.ts` — изолированный скрипт с доступом к API расширения.
- `entrypoints/app.ts`, `core/app.ts` — приложение в контексте Confluence,
  где доступен TinyMCE; настройки приходят через мост сообщений.
- `entrypoints/options/` — страница настроек.
- `core/` — типы, реестр модулей, настройки, сообщения, темы, горячие клавиши.
- `features/<имя>/definition.ts` — название и настройки модуля, только данные.
- `features/<имя>/index.ts` — реализация модуля в контексте страницы.
- `core/definitions.ts` и `core/registry.ts` автоматически обнаруживают описания и реализации соответственно.
- `assets/`, `public/icon/`, `scripts/make-icons.mjs` — исходник и сборка иконки.

Описание экспортирует объект `FeatureDefinition` из `core/types.ts` и не импортирует
реализацию. Реализация экспортирует `Feature`, дополняя описание действиями и `setupEditor`.
Options, storage и bridge используют только описания; background читает только hosts.
На верхнем уровне файлов не обращайтесь к странице: инициализацию выполняйте при запуске.
Обработчики и элементы редактора убирайте функцией очистки из `setupEditor`.
Каркас перезапускает только модуль с изменёнными настройками; смена редактора пересоздаёт все.
`startApp()` возвращает единую функцию очистки; при удалении хоста UI приостанавливается,
но мост остаётся доступным для повторного включения. Не нарушайте back/forward cache.
Цвета UI берите из `--ct-*` в `core/theme.ts`, чтобы следовать теме Confluence.
Новые функции не должны требовать правки других модулей.

## Согласованное поведение

Панель форматирования содержит четыре кнопки: очистить стиль, красный зачёркнутый,
зелёный, жёлтый. Клавиши по умолчанию Alt+Z/X/C/V; привязка к физической клавише
должна работать и в русской раскладке. Цвета по умолчанию #C9372C, #1F845A,
#946F00 записываются через соответствующие переменные палитры Confluence.

Панель появляется по Ctrl либо, если включена настройка, после отпускания левой
кнопки мыши при выделении. Положение — у конца выделения. Не окрашивайте
невыделенные вложенные пункты списка через наследование стилей от li.
Пункты форматирования в плавающем меню не нужны; на плавающей кнопке волшебная палочка.
Настройки клавиш объединены в блок, общий сброс возвращает настройки модуля к умолчаниям.

## Скилы Codex

Проектные скилы находятся в `.agents/skills/`:

- `find-skills` — поиск и установка дополнительных скилов.
- `code-review-and-quality` — ревью правильности, простоты, архитектуры,
  безопасности и производительности.
- `typescript-best-practices` — рекомендации по TypeScript.

Перед применением читайте соответствующий `SKILL.md`. Ссылки скилов на другие,
неустановленные скилы не являются основанием для автоматического добавления
зависимостей или усложнения архитектуры. Приоритет имеют задача пользователя
и существующий стек.

## Проверка и git

Тестовый стенд: http://confluence.ideveloplab.ru:8095/.
Данные на нём тестовые. Учётные данные берите только из предоставленного пользователем
контекста или локальных заметок и не публикуйте их. Установка расширения в Chrome
и выполнение кода в странице — разные способы проверки; явно указывайте способ.

Не меняйте сторонний образец, не добавляйте зависимости без необходимости.
Не коммитьте `node_modules/`, `.output/`, `.wxt/`, секреты или пароли.
Коммиты и отправку в удалённый репозиторий выполняйте по просьбе пользователя.
